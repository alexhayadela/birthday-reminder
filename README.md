# Birthday Reminder

A small Python automation that checks birthdays stored in Supabase and sends personalized daily email reminders when someone's birthday is two days away.

The email also includes the next four upcoming birthdays relevant to each recipient.

## How it works

Every day, GitHub Actions runs the application:

1. Fetch people, their birthdays, and their notification recipients from Supabase.

2. Calculate each person's next birthday.

3. Find birthdays exactly two days away.

4. Group birthdays by recipient so each person only receives notifications about people they are interested in.

5. If there is a reminder, build an email containing:

   * The birthday reminder.
   * The next four upcoming birthdays relevant to that recipient.

6. Send the notification by email.

The notification layer is separated from the birthday logic so another channel, such as WhatsApp, can be added later without changing the birthday calculation.

## Requirements

* Python 3.13

* A Supabase project

* A Gmail account or another SMTP-compatible email account

* GitHub Actions for scheduled execution

## Database

The application uses three Supabase tables:

* `people` stores people and their birthdays.
* `recipients` stores people who should receive notifications.
* `person_recipients` connects people to the recipients who are interested in their birthdays.

This allows multiple recipients to receive notifications about the same person, while each recipient only receives birthdays that are relevant to them.

Run the following SQL in the Supabase SQL Editor:

```sql
create table if not exists people (
    id bigint generated by default as identity primary key,
    name text not null,
    birthday_month smallint not null
        check (birthday_month between 1 and 12),
    birthday_day smallint not null
        check (birthday_day between 1 and 31)
);

create table if not exists recipients (
    id bigint generated by default as identity primary key,
    name text not null,
    email text not null unique
);

create table if not exists person_recipients (
    person_id bigint not null
        references people(id)
        on delete cascade,

    recipient_id bigint not null
        references recipients(id)
        on delete cascade,

    primary key (person_id, recipient_id)
);
```

Only the month and day are stored because the year of birth is not required.

Example `people` table:

```text
id | name  | birthday_month | birthday_day
---+-------+----------------+-------------
1  | Anna  | 9              | 27
2  | Marc  | 10             | 1
3  | John  | 12             | 14
```

Example `recipients` table:

```text
id | name   | email
---+--------+----------------------
1  | Me     | me@example.com
2  | Sister | sister@example.com
```

The `person_recipients` table defines which recipients are interested in which people:

```text
person_id | recipient_id
----------+-------------
1         | 1
1         | 2
2         | 1
3         | 2
```

In this example, both `Me` and `Sister` receive notifications about Anna, `Me` receives notifications about Marc, and `Sister` receives notifications about John.

More recipients can be added without changing the `people` table or the application structure.

## Local configuration

Create:

```text
conf/.env
```

with:

```env
SUPABASE_URL=your_supabase_url

SUPABASE_API_KEY=your_supabase_api_key

EMAIL_HOST=stmp.gmail.com

EMAIL_PORT=465

EMAIL_USER=your_email@gmail.com

EMAIL_PASSWORD=your_email_password
```

Do not commit this file.

For Gmail, `EMAIL_PASSWORD` should normally be an **App Password**, not your normal Google account password.

`EMAIL_USER` is the account used to send the emails. The email addresses receiving the notifications are stored in the `recipients` table.

Create a virtual environment:

```bash
python3.13 -m venv .venv
```

Activate it:

### macOS / Linux

```bash
source .venv/bin/activate
```

### Windows

```powershell
.venv\Scripts\activate
```

Install dependencies:

```bash
pip install -r requirements.txt
```

## Run locally

Run:

```bash
python -m src.main
```

The application will check the database and send personalized emails if someone has a birthday exactly two days from today.

Each recipient only receives information about the people associated with them.

## GitHub Actions

The workflow runs every day at 08:00 UTC.

It can also be started manually using the `workflow_dispatch` option in GitHub Actions.

The following GitHub repository secrets are required:

```text
SUPABASE_API_KEY
SUPABASE_URL
EMAIL_HOST
EMAIL_PORT
EMAIL_USER
EMAIL_PASSWORD
```

The workflow passes these values to the application as environment variables.

## Reminder logic

If today is September 25 and the database contains:

```text
Anna  — September 27
Marc  — September 28
John  — October 1
Sarah — October 14
```

and the recipients are configured so that both `Me` and `Sister` are interested in Anna, while only `Me` is interested in Marc, the email to `Me` contains:

```text
🎂 Birthday reminder

Anna has a birthday in 2 days (Sunday, 27 September).

📅 Next birthdays

Anna  — Sunday, 27 September (2 days)

Marc  — Monday, 28 September (3 days)

John  — Thursday, 1 October (6 days)

Sarah — Wednesday, 14 October (19 days)
```

The email to `Sister` only contains the birthdays associated with `Sister`.

If nobody has a birthday exactly two days away for a particular recipient, no email is sent to that recipient.

## Future notification channels

The notification interface is intentionally separated from the pipeline.

Currently:

```text
pipeline

    ↓

notifier

    ↓

email
```

A future implementation could use:

```text
pipeline

    ↓

notifier

    ↓

WhatsApp
```

without changing the birthday calculation logic.
